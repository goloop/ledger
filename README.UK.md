# ledger

`ledger` веде гаманці передплачених кредитів для Go-сервісу: два кошики на
акаунт (бонусні кредити, що згоряють, і куплені, що не згоряють ніколи),
журнал усіх рухів, який лише дописується, резерви для дій, що ще
виконуються, і ключ на кожному русі, щоб нічого не застосувалося двічі.

Це рушій під кредитами, окремими платними речами й лімітами планів - та
частина білінгу, яка має бути правильною раніше за все інше: баланс, за який
клієнт заплатив. Лише стандартна бібліотека.

Англійська версія: **[README.md](README.md)**.

## Яку проблему розв'язує

Кожен продукт, що продає використання, пише той самий гаманець і помиляється
в тих самих місцях:

- **Подвійне нарахування.** Провайдер доставляє вебхук двічі або воркер
  повторює запит після таймауту - і клієнт отримує кредити двічі.
- **Оплачені невдачі.** Дію оплатили, вона впала, а кредити зникли; або
  повернулися не в той кошик, і безкоштовний бонус став купленими кредитами.
- **Гонки.** Два запити одного користувача одночасно витрачають той самий
  баланс, і гаманець іде в мінус.
- **Згоряння, якого немає.** Бонуси й ліміти планів мали згоряти, щомісячна
  задача пропустила запуск - і вони накопичуються.
- **Повернення після витрати.** Chargeback приходить за вже використані
  кредити, і код або падає, або лишає від'ємний баланс. Або приходить, поки
  їх тримає резерв дії, дія падає, і повернені гроші лишають кредити в
  гаманці.
- **Немає сліду.** У тікеті питають «куди поділися мої 300 кредитів», а
  відповісти можна лише числом у колонці.

`ledger` розв'язує це один раз: кожен рух має ключ і ідемпотентний, резерв
завершується рівно один раз, оновлення одного акаунта впорядковує сховище,
бонусний кошик згоряє сам, сторнування забирає залишок - разом із
резервами в дорозі - і повідомляє про нестачу, а кожен рух - це запис із балансами після нього, і `Audit` доводить,
що вони сходяться.

## Можливості

- **Два кошики.** Бонусні кредити (нарахування, ліміти планів) згоряють і
  витрачаються першими; куплені не згоряють і лише їх забирає повернення.
- **Ідемпотентність за ключем.** Повторний виклик нічого не змінює й каже, що
  зробив перший; той самий ключ для іншого руху - помилка.
- **Резерви.** `Hold`, потім `Capture` чи `Release`; повернення відновлює
  точно ті кошики. `ReleaseStale` прибирає за воркерами, що впали.
- **Ліміти планів.** `Grant.Replace` починає новий період замість
  накопичувати старий; `Origin` фіксує, чи бонус був подарунком, чи частиною
  оплаченого плану.
- **Сторнування** для повернень і chargeback: дістає резерви в дорозі,
  повідомляє про нестачу і для відмови бере все або нічого (`Exact`).
- **Історія**, що лише дописується, без пропусків і з самоперевіркою
  (`Audit`).
- **Змінне сховище.** Невеликий інтерфейс `Store`; `MemoryStore` як еталон;
  `ledgertest.Store` перевіряє сховище в базі на той самий контракт, включно з
  конкурентністю.
- **Нуль залежностей.**

## Швидкий старт

```go
l := ledger.New(ledger.NewMemoryStore()) // у продакшні - сховище в базі

// Оплачений пакет. Вебхук може прийти тричі; ключ робить це одним рухом.
err := l.Deposit(ctx, "user-42", ledger.Deposit{Key: "txn_01", Amount: 1000_00})

// Вітальні кредити, що згорять за місяць.
err = l.Grant(ctx, "user-42", ledger.Grant{
	Key: "welcome", Amount: 300_00, Until: time.Now().AddDate(0, 1, 0),
})

// Дія за 25 кредитів: спершу бонусні, потім куплені.
h, err := l.Hold(ctx, "user-42", ledger.Charge{Key: "job-7", Amount: 25_00, Ref: "pdf-to-word"})
if errors.Is(err, ledger.ErrInsufficient) {
	return errPaymentRequired // 402
}
if err != nil {
	return err // ErrHoldExists: у задачі вже є резерв - не запускати вдруге
}
// Розрахунок - на контексті, який клієнт не скасує, з власним строком.
settle, cancel := context.WithTimeout(context.WithoutCancel(ctx), 10*time.Second)
defer cancel()
if err := run(job); err != nil {
	_ = l.Release(settle, "user-42", h.ID) // невдача нічого не коштує
	return err
}
// Дія виконана: на помилці Capture його повторить воркер. Не звільняти тут
// і не відкладати Release через defer - це подарувало б дію.
err = l.Capture(settle, "user-42", h.ID)
```

Суми - в одиниці, яку обираєте ви; рекомендовано соті частки кредиту, тож
`1000_00` - це 1000 кредитів.

## Моделі ціноутворення

Ledger не знає цін і планів; він переміщує кредити. Ось моделі, які він
несе, і що лишається вашому застосунку:

| Модель | Приклад | Робить ledger | Робить застосунок |
|---|---|---|---|
| **Кредити, оплата за дію** | виклики API, конвертації, AI-запити | `Deposit` пакета, `Hold`/`Capture` за дію | прайс-лист, пакети, курс |
| **Окремі платні речі** | «Галерея 25 GB x 15 днів: €1.50» | `Spend` ціни речі з гаманця | сама річ і строк її життя |
| **План з лімітом** | «Pro: 1000 кредитів на місяць» | `Grant{Replace, OriginPlan}` щоперіоду | підписка та її права |
| **План + понад ліміт** | спершу ліміт, потім куплені | бонус витрачається першим, куплені - після | нічого більше |
| **Строки: місяць / рік / два роки** | $15 / $60 / $100 | ліміт щомісяця, хоч який строк | строк - через платіжного провайдера |
| **Безкоштовний рівень, акції** | вітальні кредити, щомісячний бонус | `Grant{OriginPromo}` зі строком | хто на нього заслуговує |
| **Гаманець команди** | один баланс на команду | акаунт - це id команди | хто може витрачати |
| **Повернення, відмова, chargeback** | 14 днів на відмову | `Reverse` з нестачею | правила, хто має право |

Для чого ledger **не** потрібен: **безлімітний** план (це право плюс обмеження
частоти, рахувати нічого), **оренда місткості** на кшталт «50 GB на рік»
(ліміт на те, що існує, а не баланс, що витрачається) і **разова ліцензія**
(право, а не кредити). Це рядки у вашій таблиці прав; їх продає платіжний
провайдер, а ledger не заважає. Довідник показує кожну модель у коді:
[Моделі ціноутворення](DOC.UK.md#моделі-ціноутворення).

## Реальний приклад

Paddle продає пакет кредитів; вебхук їх нараховує і забирає, коли гроші
повертаються.

```go
wh := paddle.NewWebhook(os.Getenv("PADDLE_WEBHOOK_SECRET"))

http.HandleFunc("POST /webhooks/paddle", func(w http.ResponseWriter, r *http.Request) {
	ev, err := wh.ParseRequest(r)
	if err != nil {
		http.Error(w, "bad signature", http.StatusBadRequest)
		return
	}
	if err := handle(r.Context(), ev); err != nil {
		http.Error(w, "retry", http.StatusInternalServerError) // Paddle надішле ще раз
		return
	}
	w.WriteHeader(http.StatusOK)
})

// handle безпечно запускати двічі для однієї події: кожен виклик ledger має ключ.
func handle(ctx context.Context, ev *paddle.Event) error {
	switch ev.Type {
	case paddle.EventTransactionCompleted:
		tx, err := ev.Transaction()
		if err != nil {
			return err
		}
		p, err := purchases.ByTransaction(ctx, tx.ID) // ваша таблиця
		if err != nil {
			return err
		}
		// id транзакції - це ключ: повторна доставка нічого не змінює.
		return l.Deposit(ctx, p.Account, ledger.Deposit{Key: tx.ID, Amount: p.Credits, Ref: tx.ID})

	case paddle.EventAdjustmentCreated, paddle.EventAdjustmentUpdated:
		adj, err := ev.Adjustment()
		if err != nil {
			return err
		}
		if adj.Action != paddle.ActionRefund && adj.Action != paddle.ActionChargeback ||
			adj.Status != paddle.AdjustmentApproved {
			return nil
		}
		p, err := purchases.ByTransaction(ctx, adj.TransactionID)
		if err != nil {
			return err
		}
		// Одне повернення - один запис, один ключ, спільний із відмовою, яку
		// почав застосунок, тож повернення ніколи не сторнується двічі.
		r, err := refunds.ForProvider(ctx, p, adj.ID) // ваша таблиця
		if err != nil {
			return err
		}
		_, err = l.Reverse(ctx, p.Account, r.Reversal()) // "refund:" + r.ID
		return err
	}
	return nil
}
```

## API коротко

| Виклик | Що робить |
|---|---|
| `New(store, opts...)` | ledger над сховищем |
| `Grant` | додати бонусні кредити зі строком (`Replace` - новий період) |
| `Deposit` | додати куплені кредити |
| `Hold` / `Capture` / `Release` | відкласти ціну, потім завершити |
| `Spend` | списати одразу |
| `Reverse` | забрати куплені кредити після повернення коштів, разом із резервами в дорозі |
| `Adjust` | ручне виправлення |
| `Balance` | гаманець зараз, з урахуванням згоряння |
| `Entries` | історія, найновіші першими, посторінково |
| `Audit` | довести, що історія сходиться |
| `ReleaseStale` | повернути резерви, лишені воркерами, що впали |
| `NewMemoryStore` | еталонне сховище |
| `ledgertest.Store` | набір перевірок для вашого сховища |
